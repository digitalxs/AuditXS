AuditXS documentation

AuditXS is a transparent, reversible Linux security audit and hardening tool for Debian, Ubuntu, Pop!_OS, Arch, Fedora and openSUSE. Audits are strictly read-only; every fix is explained first, applied only with consent, and recorded in a snapshot that auditxs rollback can restore.

User manualInstalling, auditing, hardening, rollback, baselines, fleet mode and every command. Check catalogueEvery check: what it inspects, why it matters, what the fix changes and how it reverts. Error catalogueEvery AXnnnn error number with a plain explanation and fix. ArchitectureThe engine, the check API, the snapshot format and the fleet data flow. Security guideCybersecurity best practices that pair with AuditXS hardening. ComplianceCIS Benchmark, DISA STIG alignment and NIST CSF 2.0 mappings. Web UIThe Material Design web interface — local by default, or reachable on the network — its security model and usage. RoadmapWhat shipped in each release, what comes next, and deliberate non-goals. ChangelogRelease notes for every AuditXS version. Developer guideContributing: code map, check API, debugging, testing and releases.

Quick start

git clone https://github.com/digitalxs/AuditXS.git
cd AuditXS
sudo ./setup.sh           # or:  sudo ./install-gui.sh  (graphical installer)

sudo auditxs audit        # read-only audit + HTML/JSON report + score
sudo auditxs harden       # review and apply fixes, one by one, with consent
sudo auditxs rollback latest

The full command reference lives in the user manual; the complete check documentation is in the check catalogue.
